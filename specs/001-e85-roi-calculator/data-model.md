# Data Model: Calculateur de rentabilité E85

**Date**: 2026-10-19
**Feature**: [spec.md](./spec.md)
**Persistence**: One active JSON dataset in browser storage, with manual JSON-file import/export

## Ownership and Relationships

```text
Browser Local Dataset (1) ──────── (*) Vehicle (1) ──────── (*) Fill
```

The browser stores one active dataset for the current origin/profile. A person may keep a separate exported JSON file, but the application does not authenticate file ownership or provide account isolation. A vehicle belongs to one dataset, and a fill belongs to exactly one vehicle. Entity IDs are generated by the client and unique within the active dataset.

## Entities

### Local Dataset

Represents the active user's working data on one browser/device. The person controls transfer and backup by exporting/importing a complete JSON file; browser storage itself is not an account, authentication mechanism, or confidentiality boundary.

| Field | Type | Required | Rules |
|---|---|---:|---|
| `schemaVersion` | Integer | Yes | Supported version of the exported/imported document. |
| `updatedAt` | ISO 8601 UTC datetime | Yes | Updated when the working dataset changes. |
| `vehicles` | Vehicle array | Yes | Starts empty; contains the current dataset's vehicles. |

Do not store passwords, user IDs, or authentication tokens. A separate JSON file is associated with a person only by their own choice and file handling.

### Vehicle

Represents one vehicle and its Bioflex box amortization account.

| Field | Type | Required | Rules |
|---|---|---:|---|
| `id` | UUID string | Yes | Generated in the browser; unique within the dataset. |
| `make` | String | Yes | Non-empty after trimming. |
| `model` | String | Yes | Non-empty after trimming. |
| `boxCostEur` | Number | Yes | Strictly positive; creation form defaults to 1000 EUR, which the user confirms or changes. |
| `installDate` | `YYYY-MM-DD` date | Yes | Valid calendar date. |
| `createdAt` | ISO 8601 UTC datetime | Yes | Set by the browser when the vehicle is created. |
| `fills` | Fill array | Yes | Starts empty; only fills for this vehicle. |

### Fill

Represents one E85 fill. Raw inputs are persisted; computed amounts are derived so they cannot become stale after an input correction.

| Field | Type | Required | Rules |
|---|---|---:|---|
| `id` | UUID string | Yes | Generated in the browser; unique within the dataset. |
| `recordedAt` | ISO 8601 UTC datetime | Yes | Set by the browser when the fill is recorded. |
| `e85PricePerLitreEur` | Number | Yes | Strictly positive. |
| `sp95PricePerLitreEur` | Number | Yes | Strictly positive. |
| `litres` | Number | Yes | Strictly positive. |

Computed values are derived locally and are not persisted:

- `e85CostEur = e85PricePerLitreEur × litres`
- `sp95EquivalentCostEur = sp95PricePerLitreEur × (litres × 0.8)`
- `savingEur = sp95EquivalentCostEur - e85CostEur`
- `totalSavingsEur = sum(savingEur for this vehicle's fills)`
- `remainingToAmortizeEur = boxCostEur - totalSavingsEur`

Use decimal-safe arithmetic for monetary calculations and round at the currency boundary to two decimal places. A negative saving and a negative remaining balance are valid values.

## File Envelope

The complete dataset is serialized as one JSON document in browser storage. Import/export operates on this same envelope. The browser storage key must be namespaced to this application; because localStorage is origin-scoped rather than path-scoped, use a unique key to avoid collisions with other projects hosted on the same `github.io` origin.

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-10-18T19:00:00.000Z",
  "vehicles": [
    {
      "id": "a1c6d80a-40a4-4c30-ae4e-64ea3bb48afe",
      "make": "Peugeot",
      "model": "308",
      "boxCostEur": 1000,
      "installDate": "2026-10-18",
      "createdAt": "2026-10-18T19:05:00.000Z",
      "fills": [
        {
          "id": "844b82a0-90ec-4879-a0b0-1e82a8893b18",
          "recordedAt": "2026-10-18T19:10:00.000Z",
          "e85PricePerLitreEur": 0.9,
          "sp95PricePerLitreEur": 1.8,
          "litres": 40
        }
      ]
    }
  ]
}
```

The example values are illustrative. The document contains no account identity or credentials.

## Invariants and Validation

- IDs are unique within the active local dataset; no application account or user-level authorization exists.
- A fill's `recordedAt` is not earlier than its vehicle's installation date.
- Required strings are trimmed and non-empty; numeric inputs are finite and strictly positive.
- No derived ROI value is trusted as persisted source data; calculations are recomputed from raw fill inputs.
- Every import validates the complete document, schema version, fields, and size before replacing the active dataset. Invalid imports leave active data unchanged.
- Importing a valid file into a non-empty dataset requires explicit confirmation because it replaces the active working copy.
- Export includes the entire active dataset as plaintext JSON; the application does not encrypt or authenticate the file.
- Browser storage can be cleared, evicted, or unavailable; exported files are the only user-controlled backup and transfer mechanism.

## Lifecycle

1. The application loads the active dataset from the current browser profile or initializes an empty dataset.
2. The user may import a personal JSON file; the app validates it fully and confirms before replacing active data.
3. The user creates vehicles and fills; the app updates browser storage and recomputes ROI values locally.
4. The user exports the whole active dataset as a JSON download for backup or manual transfer to another device.
5. On another device, the user manually imports the exported file; there is no automatic sync or authentication.
